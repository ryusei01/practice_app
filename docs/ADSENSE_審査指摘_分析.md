# AdSense 審査指摘の読み方（案）

対象: `ai-practice-book.com`（2026-10-16 時点の本番と、このリポジトリの広告実装）

コンソールの文言は **3 件が別問題** として並んでいる。上 2 件を直しても、下のポリシー違反が残っている限り広告は出ない。逆に、ポリシーだけ直してもお支払い情報とサイトのリンクが未完了なら「収益化を開始」にはならない。

| コンソールの見出し | 種類 | コードを直す話か |
| --- | --- | --- |
| お支払い情報を追加し、サイトを AdSense にリンク | アカウント手続き | ほぼ管理画面の作業 |
| サイトの所有権を確認してください / 要確認 / 広告を表示できない | サイトステータス | 確認用の材料は本番に既にある。ステータスが落ちている主因は下のポリシー違反の可能性が高い |
| パブリッシャーのコンテンツを含まない画面 / 有用性の低いコンテンツ | プログラムポリシー | ここが再審査の本丸 |

---

## 1. 手続き（警告）

「収益化を開始するには、お支払い情報を追加し、サイトを AdSense にリンク」は、コンテンツの良し悪しとは別のチェックリスト。

- お支払いプロファイル（住所・税務・受け取り方法）が未完了だと、サイトがポリシーを通っていても収益化は始まらない。
- 「サイトをリンク」は、AdSense のサイト一覧で `ai-practice-book.com` が追加済みかつステータスが「準備完了」になること。コードを置いただけでは完了にならない。

これは管理画面で埋める作業。再送の前提条件ではあるが、今回の「ポリシー違反が見つかりました」の理由ではない。

---

## 2. 所有権と「広告を表示できない」

本番では次が既に返っている。

- `https://ai-practice-book.com/ads.txt`  
  `google.com, pub-9679910712332333, DIRECT, f08c47fec0942fa0`
- 全 HTML の `<head>` に AdSense スクリプト（`ca-pub-9679910712332333`）
- 同じ `<head>` に `google-site-verification`（`inject-adsense.js` がビルド時に注入）

つまり「確認用のタグや ads.txt がサイトに無い」状態ではなさそう。コンソールの「要確認」「広告を表示できない」は、次のどちらか（または両方）でステータスが落ちているときの表示だと見る。

1. ポリシー違反でサイトが配信停止になっている（今回の本文）。
2. お支払い情報またはサイトのリンク作業が AdSense 上で未完了のまま。

Search Console の所有権と AdSense のサイトステータスは別。meta があることと、「要確認」が消えることは一致しない。

## 3. ポリシー違反の本体

引用されている方針は次の 2 つ。

1. **パブリッシャーのコンテンツを含まない画面に、Google 配信の広告を置いてはいけない**
   - コンテンツが無い、または有用性が低い
   - 作成中
   - アラート、ナビゲーションなど、行動が目的の画面
2. **有用性の低いコンテンツ**（独自の価値がページとして読めない、未完成に見える、継続して見に来る中身が薄い）

審査はログイン後のアプリ体験より、**ログインなしで開いた URL の中身**と、**広告コードが載っている画面**を見る。このサイトは両方で引っかかりやすい。

### 3.1 最初の HTML に本文が無い

`https://ai-practice-book.com/` の生 HTML は次の状態。

- `<html lang="en">`（クローラの第一言語が英語）
- `<title>` が空
- description などの本文メタは React がマウントしたあとでしか入らない
- `<body>` はスタイルシートと空のアプリ枠。問題文・解説・教科書はソースに無い

AdSense のスクリプトだけが `<head>` の先頭にある。中身より先に広告タグが見える。

トップを描画したあとも、見えるのは機能紹介カード、料金、「準備中」、登録ボタン、法務リンク、初回のベータ案内モーダル。学習そのもの（問題・解説・教科書の本文）は別画面のクライアント保存に寄っている。

### 3.2 公開 URL が薄い

`frontend/public/sitemap.xml` にあるのは次だけ。

- `/`
- `/question-sets`
- `/tokusho`
- `/terms-of-service`
- `/privacy-policy`

法務 3 ページは定型文で、サイトの価値の証明にはならない。

`/question-sets` は問題一覧に見える URL だが、一覧は `localStorageService.getTrialQuestionSets()`（端末内ストレージ）のあとで描画する。ストレージが空の初回訪問では、描画結果が「No question sets yet. Create your first one!」になる。取得時点の本番もこの空表示だった。デフォルト問題集の投入は別処理で、HTML にも個別 URL にもなっていない。

教科書や問題の本文はアプリ内データ（CSV / ローカル）にあり、クローラが辿れる記事 URL になっていない。`robots.txt` は `/quiz/` `/set/` `/flashcard/` などを Disallow しているので、学習画面は検索にも審査の巡回にも出にくい。

結果として、外から見えるサイトは「ベータの学習アプリの入り口」と「空の一覧」と「法務」に見える。方針文の「信頼できる高品質な情報」「継続的なキュレーション」「ユーザーの関心を維持」に対して、ページとしての在庫が足りない、という判定になりやすい。

### 3.3 「作成中」がトップに出ている

方針の例そのままだ。

- トップのプレミアムとマーケットプレイスが `Preparing` / 「準備中」
- ヘッダーがベータ表記
- 初回訪問で「ベータ版です。機能・挙動・デザインは予告なく変わる」モーダル
- `premium-preparing.tsx` は見出しが「準備中」だけ
- ダッシュボードの販売者メニューに「準備中」オーバーレイ

未完成を自分で宣言している画面が、サイトの顔になっている。

### 3.4 広告が「中身の無い画面」に載っている

手動の `AdBanner` がある画面（`docs/TODO_広告.md` と同じ）:

| 画面 | その画面の役割 | 方針との対応 |
| --- | --- | --- |
| `dashboard.tsx` | メニューボタンとログアウト | ナビゲーションが目的の画面 |
| `quiz/result.tsx` | 結果。広告はスコアより上 | パラメータ無しだと 0/0 の薄い画面の先頭に広告 |
| `study-records.tsx` / `learning-plan.tsx` / `ai-dashboard.tsx` / `my-question-sets` | ログイン後の道具画面 | 記事ではなく操作 UI。中身が空のときの広告が危ない |
| `store.tsx` | ストア | 本番トップではマーケットプレイス自体が準備中 |
| `InterstitialAdModal.tsx` | 20 問ごとの全面モーダル。中身は広告と「N 秒後に閉じられます」 | パブリッシャーのコンテンツが無く、行動（閉じるまで待たせる）が目的 |

とくにインタースティシャルが一番はっきりしている。モーダルの中身は広告だけで、閉じるまで 5 秒待つ。方針の「アラートなど、行動が目的の画面には広告を置かない」にそのまま当てはまる。クイズ本文を隠して広告だけを見せる形でもある。

加えて `scripts/inject-adsense.js` は `dist` の **全 HTML** に `adsbygoogle.js` を入れる。AdSense 側で自動広告がオンだと、ログイン、登録、404、法務、準備中、空の一覧にも Google が広告を置く。手動ユニットを外しても、自動広告がオンのままだと同じ違反になる。

広告ユニット未設定時のスロットは `1234567890`（`AdBanner.web.tsx`）。本番環境変数が空だとユニットは無効で、これ自体はポリシー違反の理由ではないが、「広告を表示できない」の技術的な理由にはなる。

## 4. 何が一番まずいか（優先度の案）

再送前に効きそうな順。

1. **広告を載せてよい画面を絞る**  
   ダッシュボード（メニュー）、準備中、結果が空の画面、インタースティシャルモーダルからは `AdBanner` を外す。自動広告がオンならオフにする。広告は、問題文・解説・教科書本文が十分にある画面だけにする。
2. **「作成中」を顔にしない**  
   トップの準備中カード、ベータモーダル、販売者の準備中オーバーレイは、審査用の公開面から見えなくする。未公開機能はリンクごと出さない。
3. **ログインなしで読める中身を URL にする**  
   デフォルト問題集と教科書を、ストレージ待ちではなく最初の HTML（または静的な個別 URL）に出す。`/question-sets` の初回が「まだ問題セットがありません」のままだと、有用性の低いコンテンツの見本になる。サイトマップにその URL を足す。
4. **生 HTML のタイトルと本文**  
   JS 実行前の `<title>` が空、`lang="en"` 固定なのは、英語の空サイトに見える。タイトル・説明・主要な見出しを初期 HTML に入れる。
5. **そのあとで管理画面**  
   お支払い情報、サイトのリンク状態を確認し、上を直してから審査をリクエストする。所有権タグの再設置が先、ではない。

直すまで再送しても、同じ 2 方針（中身の無い画面への広告、有用性の低いコンテンツ）で戻る見込みが高い。
