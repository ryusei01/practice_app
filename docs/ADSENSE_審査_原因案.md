# AdSense 審査で「なにがいかんか」原因案

対象: `https://ai-practice-book.com`（2026-10-16 時点の本番 HTML / `ads.txt` / `robots.txt` とリポジトリ実装）

この文書は **Google 内部の判定理由そのものではなく、コンソール文言とサイト実態から立てた優先度付きの原因案** です。再審査前に潰す順番のたたき台として使ってください。実装変更はまだ入れていません。

関連: `docs/TODO_広告.md` / `frontend/ADSENSE.md`

---

## 1. いまコンソールに出ている指摘は「別件が重なっている」

画面に並んでいる文言は、1 つの不備ではなく **セットアップ未完了 + 所有権 + ポリシー + コンテンツ品質** が同時に出ています。

| # | コンソールの文言 | 種類 | このサイトで効いていそうな中身 |
|---|------------------|------|--------------------------------|
| A | お支払い情報を追加し、サイトを AdSense にリンク | アカウントセットアップ | 支払い未入力は運用作業。リンクは ads.txt / 広告コード / Search Console のいずれか |
| B | サイトは広告を表示できない状態です | サイト状態（結果） | C〜E が解消するまで広告は出ない |
| C | サイトの所有権を確認してください | 技術（リンク） | HTML 検証ファイルが `.html` から 308 リダイレクトされる |
| D | パブリッシャーのコンテンツを含まない画面に広告を置けない | **プログラムポリシー** | 空シェル HTML・ナビ画面・20問ごとの広告モーダル・「準備中」 |
| E | 有用性の低いコンテンツ | **品質（valuable inventory）** | Web アプリで、クローラに見える独自テキストがほぼ無い |

**B は原因ではなく結果**です。A だけ直しても D/E が残れば再審査は通りません。逆に D/E を直しても、A/C が未完了なら「リンクできない / 広告を出せない」が残ります。

Google が貼っているヘルプ（質の高いサイトのヒント、ウェブマスター向けガイドライン、AdSense プログラムポリシー、AdMob ポリシー）は、Web なら **AdSense**、ネイティブなら **AdMob** が本線です。今回のドメイン審査は AdSense 側です。

---

## 2. 結論（効いている順）

審査ボット／レビュアーから見ると、今のサイトはだいたいこう見えます。

1. **記事サイトではなく学習 Web アプリ**（問題を解く・ナビする画面が本体）
2. **JS を実行しないと本文が 0 文字**（初期 HTML は空の SPA シェル）
3. **その空ページの `<head>` に AdSense スクリプトが入っている**
4. **アプリ内では、中身の薄いナビ画面と「広告だけのモーダル」に広告を置いている**
5. **トップに「ベータ」「準備中」が書いてある**

これが D（コンテンツのない画面）と E（有用性の低いコンテンツ）に、ほぼそのまま該当します。

A（支払い）と C（所有権）は別レイヤで、コンソール操作と検証ファイル配信の問題です。

---

## 3. 原因案（優先度付き）

優先度は「再審査でまた同じ指摘が返りやすいか」です。

### P0-1. クローラから見た HTML に本文が無い（D + E の本命）

**案:** AdSense / Googlebot は JS を十分に実行せず、初期 HTML だけを見る。今の本番トップは **タイトル空・本文 0 文字・広告スクリプトだけある**。

実測（User-Agent: Googlebot、2026-10-16）:

- `<title data-rh="true"></title>`（空）
- スクリプト・スタイルを除いた本文長 **0**
- `<head>` には `adsbygoogle.js?client=ca-pub-9679910712332333` と `google-adsense-account` がある
- Expo のリセット CSS で `body{overflow:hidden}`（スクロールできる記事に見えない）

これはポリシー文言の次と一致します。

- コンテンツがない、または有用性の低いコンテンツ
- （レビュアー視点では）作成中の空ページ

WebFetch で JS 実行後に取れるテキストも、トップはタイトル＋「問題集を作ってクイズと単語帳。データは端末に保存」程度で、**独自の長文コンテンツではありません**。`/question-sets` も「Question Sets / Sign In / Hide Defaults / Create…」の UI ラベルだけです。

実装上の理由:

- Expo Router の静的書き出し（SPA）。中身はクライアントでマウントされる
- メタ・本文は `frontend/app/index.tsx` の `useEffect` で後から入れる（クローラの初回 HTML には載らない）
- 本番は `frontend/scripts/inject-adsense.js` が **すべての `dist/*.html` の `<head>` に広告スクリプトを注入**する

つまり「広告コードはあるが、パブリッシャーコンテンツが HTML 上に無い」状態です。SPA で AdSense 初回審査が落ちる典型パターンです。

---

### P0-2. 広告を置いている画面が、ポリシーで禁止されている種類（D）

ポリシー: 次の画面には Google 配信広告を置けない。

- パブリッシャーのコンテンツが無い / 有用性が低い
- 作成中
- **アラート、ナビゲーションなど、行動が目的**

今の `AdBanner` 配置:

| 画面 | ファイル | 画面の性質 |
|------|----------|------------|
| ダッシュボード | `frontend/app/(app)/dashboard.tsx` | メニュー・遷移が本体（ナビゲーション画面） |
| AI ダッシュボード | `frontend/app/(app)/ai-dashboard.tsx` | 分析 UI。空なら「まだ提案がありません」 |
| 学習記録 | `frontend/app/(app)/study-records.tsx` | ユーザーデータ UI |
| 学習プラン | `frontend/app/(app)/learning-plan.tsx` | ツール画面 |
| 自分の問題集一覧 | `frontend/app/(app)/my-question-sets/index.tsx` | 一覧・操作画面 |
| クイズ結果 | `frontend/app/(app)/quiz/result.tsx` | スコア画面（記事ではない） |
| ストア | `frontend/app/(app)/store.tsx` | 本番ではリダイレクトして中身なし。開発時だけバナー |
| 20問ごとモーダル | `frontend/src/components/InterstitialAdModal.tsx` | **広告だけのオーバーレイ** |

特に効いていそうなのがインタースティシャル風モーダルです。

- `QuizEngine` が解答 20 問ごと（最終問の手前まで）に出す
- 画面は「広告」ラベル + `AdBanner` だけ
- **5 秒カウントダウンが終わるまで閉じられない**
- 学習コンテンツの上にオーバーレイ

これは次の禁止に同時に当たります。

- パブリッシャーコンテンツを含まない画面
- 行動目的（次の問題へ進む途中の割り込み）
- コンテンツを覆う広告 / 誤クリックしやすい配置（Better Ads 系）

公開トップ（`frontend/app/index.tsx`）には `AdBanner` は無いですが、**全 HTML の head に `adsbygoogle.js` がある**ため、AdSense 側で自動広告がオンなら、ボットが「コンテンツの薄い画面に広告コードがある」と判定できます。

加えて、広告の実体がある画面の多くはログイン後です。AdSense クローラはパスワードなしで見られるページを審査します。クローラに見える公開面はトップ・お試し一覧・規約類で、**広告ユニットはアプリ内**、というねじれもあります。

---

### P0-3. 「作成中」がサイト全体に出ている（D の “under construction” + E）

ポリシーは **作成中の画面に広告を置けない** と明記しています。今の公開トップは、未完成を自分から宣言しています。

- 初回「ベータ版です。機能・挙動・デザインは予告なく変更される場合があります。」
- プレミアム「準備中」
- マーケットプレイス「準備中」
- ヘッダー / タイトルに `Ver.β`

レビュアーから見ると「公開途中のアプリの壳に広告コードを挿した」に見えます。有用性の低いコンテンツ側のチェックリスト（信頼できる情報、継続的なメンテナンス、ユーザーの関心）とも逆方向です。

---

### P1. サイト種別そのものが AdSense 初回審査と相性が悪い（E）

Google の「有用性の低いコンテンツ」は、広告を載せるサイトに次を求めます。

- 独自の価値がある情報・ツール・サービス
- 継続的なキュレーション
- ユーザーの純粋な関心（一定のトラフィック・定着）

このプロダクトの価値は **問題を解く体験** にあり、ブログ記事のようなクロール可能なテキストではありません。

公開でインデックス対象なのは sitemap 上ほぼこれだけです。

- `/` ランディング（短い宣伝＋CTA）
- `/question-sets` お試し一覧（UI）
- `/tokusho` `/terms-of-service` `/privacy-policy`（法定・規約。広告用コンテンツではない）

一方、中身のある問題文・教科書はクライアント側データで、`robots.txt` は `/quiz/` `/set/` `/flashcard/` を Disallow しています。クローラは **本体コンテンツに行けない** 設計です。

コミュニティでも、ツール系 SPA / Web アプリは自動審査で「low value / insufficient content」になりやすく、人が見る枠は相当なトラフィックが付いてから、という話が多いです。広告コードを直すだけでは E は消えません。

「独自の価値」はアプリとしてはあるが、**AdSense が審査できる形（公開 HTML の十分な独自テキスト）になっていない**、が正確です。

---

### P1. 所有権・リンク（C / A の技術側）

コンソールの「サイトの所有権を確認してください」「サイトを AdSense にリンク」に対応する案です。

今入っているもの:

| 手段 | 状態 | メモ |
|------|------|------|
| `ads.txt` | `https://ai-practice-book.com/ads.txt` は 200 で配信 | `google.com, pub-9679910712332333, DIRECT, f08c47fec0942fa0` |
| `<head>` の AdSense スクリプト / `google-adsense-account` | 全 HTML に注入済み | リンク用としては足りるほう |
| メタ `google-site-verification` | 初期 HTML にあり | Search Console メタ方式ならこちらが本命 |
| HTML ファイル `public/google644c9dfdc82bc46a.html` | **要確認** | 下記 |

実測:

```
GET /google644c9dfdc82bc46a.html  →  308 Location: /google644c9dfdc82bc46a
GET /google644c9dfdc82bc46a       →  200 本文は検証用テキスト
```

Search Console / AdSense の HTML ファイル検証は **指定 URL がリダイレクト無しで、そのファイル本文を返す** ことを要求しがちです。Expo / Cloudflare が `.html` を剥がすと、所有権確認だけ失敗します。

メタタグ方式で既に Search Console が「確認済み」なら C は解消している可能性もあります。コンソールがまだ「所有権を確認」と出すなら、HTML ファイル方式を使っているか、AdSense 側のサイトリンク操作が未完了です。

支払い情報（A の前半）はコードでは直せません。AdSense の「お支払い」に口座・住所を入れる作業です。

---

### P2. プライバシーポリシーが AdSense 必須事項を満たしていない

AdSense はプライバシーポリシーに、おおむね次を書けと求めています。

- Google など第三者配信が Cookie で広告すること
- 過去のアクセス情報に基づく広告であること
- [広告設定](https://www.google.com/settings/ads) でパーソナライズド広告を無効にできること
- 第三者配信のオプトアウト（aboutads.info 等）

`frontend/app/(public)/privacy-policy.tsx` の Cookie 節は **Google Analytics だけ** です。AdSense / 広告 Cookie の記述がありません。単体で D/E の主因にはなりにくいですが、ポリシーチェックリストでは減点です。

運営者情報・問い合わせ・特商法・利用規約は公開トップから辿れます。ここは比較的足りています。

---

### P2. 本番の広告ユニット ID がプレースホルダ

`frontend/src/components/AdBanner.web.tsx`:

```ts
const WEB_AD_SLOT = process.env.EXPO_PUBLIC_AD_SLOT_WEB || "1234567890";
```

`docs/TODO_広告.md` でも「本番では無効想定」と書いてあります。自動広告（head の `adsbygoogle.js`）とは別で、**手動ユニットは審査用の実スロットになっていない**可能性があります。審査そのものより、承認後に広告が出ない原因になりやすいです。

---

### P3. その他（副因になりうる）

- **ログイン必須ページに広告がある**のに、AdSense クローラ用のログインは無い。審査対象は公開面だけ、というズレ。
- **ストアは本番で中身なし**（`store.tsx` が dashboard へ replace）。準備中の画面にコードが残っている。
- **sitemap の lastmod が 2026-04**。コンテンツが増えている印象をクローラに与えにくい（主因ではない）。
- ネイティブの AdMob は別審査。Web の AdSense 不合格は AdMob を自動では通しません。

## 4. コンソール指摘 → このリポジトリでの対応方針（案）

実装はまだしない前提の、再審査前チェックリストです。

### A. お支払い情報 / サイトをリンク

1. AdSense「お支払い」に情報を入れる（コード外）。
2. サイトをサイトリストに追加し、リンク完了まで進める。
3. リンク手段はどれか 1 つでよい。今は ads.txt + head コードがあるので、**所有権（C）が通ればリンクは揃いやすい**。
4. Search Console で `ai-practice-book.com` が確認済みか見る。未確認ならメタタグ方式を優先（初期 HTML に既にある）。

### C. 所有権

1. HTML ファイル方式を使うなら、`/google644c9dfdc82bc46a.html` が **308 せず 200 で検証テキストだけ**を返すようにする（Cloudflare / Expo の拡張子剥がしを除外）。
2. 使わないなら、Search Console をメタで確認済みにして AdSense に連携する。

### D. コンテンツのない画面の広告

審査を通すなら、少なくとも次が必要です。

1. **広告だけの画面をやめる。** `InterstitialAdModal`（20問ごと、5秒強制）は Web の AdSense では外す。ネイティブ AdMob の正規インタースティシャルとは別物。
2. **ナビ・空・ローディング・エラー・準備中に `AdBanner` を出さない。** ダッシュボード（メニュー）からも外す。
3. 出すなら「問題文・解説・教科書本文など、パブリッシャーコンテンツが十分ある画面の下」だけ。
4. 自動広告を使うなら、ログイン・登録・OTP・結果だけ・空一覧を除外する。審査中は自動広告オフの方が安全。
5. 全 HTML へ無条件注入している `inject-adsense.js` は、審査用には「コンテンツページの head だけ」に絞る案がある。ただし所有権リンク用コードはトップに残す必要がある。

### E. 有用性の低いコンテンツ

広告配置を直すだけでは足りません。審査ボットが読める **独自の長文** が要ります。

現実的な案（優先度順）:

1. **プリレンダ / SSR**して、トップ・問題集の紹介・教科書を初期 HTML に載せる。今の「JS 後の UI」だけでは E はほぼ消えない。
2. 公開の **使い方・解説記事・教科書の HTML ページ**を増やす（アプリの裏にブログを足す、ではなくサイトの主面にする）。
3. 「ベータ」「準備中」を、本当に未提供なら画面から消すか、提供開始してから再申請する。
4. `robots.txt` で問題・教科書を全部 Disallow している現状を見直し、**公開してよい解説・サンプル問題は Allow + sitemap** する。
5. トラフィックと定着（リピート学習）がほぼ無い段階での再申請は、E が再発しやすい。

運営として「学習アプリの体験が価値」なのはその通りですが、**AdSense 初回審査はそれを体験としては評価せず、公開テキスト量と完成度で落とす**、と考えた方がよいです。

## 5. 再申請してよいか（今のままでは弱い）

今のままで「審査をリクエスト」しても、D と E が再掲される可能性が高いです。

最低限、再申請前に揃えておきたい状態:

- [ ] 支払い情報を入れた
- [ ] Search Console 確認済み、または `.html` 検証ファイルがリダイレクト無し
- [ ] 広告だけのモーダルを Web から外した
- [ ] ナビ / 空 / 準備中に広告を出していない
- [ ] クローラが JS 無しで、トップとコンテンツページに十分な独自テキストを読める
- [ ] トップから「作成中」印象を消した（または本当に完成してから出す）
- [ ] プライバシーポリシーに AdSense Cookie の必須文言を足した

それでも Web アプリのまま自動審査が通らないことはあります。その場合の逃げ道は、

- ネイティブアプリは AdMob（画面ポリシーは似ているが、アプリとして審査される）
- コンテンツサイト（解説・教科書）を別 URL で育てて、そこで AdSense を通す
- 広告以外（プレミアム）を Web の主マネタイズにする

です。
