# AdSense 審査・ポリシー警告の分析（ai-practice-book.com）

> 対象: AdSense コンソールに表示された「要確認」「ポリシー違反」「有用性の低いコンテンツ」等  
> 調査日: 2026-10-16（リポジトリ `frontend/` と本番 URL の静的取得を参照）

---

## 1. コンソール表示の整理

| 表示 | 種別 | 意味 |
|------|------|------|
| お支払い情報を追加し、サイトを AdSense にリンク | **手続き** | 審査・配信開始の前提。ポリシー違反とは別 |
| サイトの所有権を確認 | **手続き** | Search Console / メタタグ / `ads.txt` 等 |
| サイトは広告を表示できない状態 | **結果** | 上記 + ポリシー未達の総合状態 |
| パブリッシャーのコンテンツを含まない画面での広告 | **ポリシー** | 実装・ページ種別の問題が疑わしい |
| 有用性の低いコンテンツ | **ポリシー** | サイト全体の「独自価値・量・完成度」の問題が疑わしい |

**重要:** 「支払い情報」「サイトリンク」「所有権」だけ直しても、ポリシー 2 項目が残っている限り再審査は通りにくい。逆に、ポリシー対策だけしても手続き未完了では配信開始できない。

---

## 2. 想定される主因（優先度順）

### A. サイト全体が「有用性の低い／未完成」に見える（最有力）

AdSense は **検索ユーザー向けの独自コンテンツ** と **完成度** を強く見る。現状の公開面は次のシグナルが重なる。

1. **ベータ・準備中の明示が多い**
   - タイトル・ヘッダ: `Ver.β`
   - トップ: ベータ版モーダル、「Premium Plan / Marketplace は **準備中**」
   - → 「作成中である」ページに近い印象（ポリシー文言と一致しやすい）

2. **インデックス可能な URL が少ない**
   - `public/sitemap.xml` は **5 URL のみ**（`/`, `/question-sets`, 特商法・規約・プライバシー）
   - デフォルト問題集・教科書・各クイズの **個別ランディング URL がサイトマップに無い**
   - 問題・解説の本文は CSV / クライアント読み込み中心で、**クローラが読める HTML として薄い**

3. **アプリ型 SPA（Expo 静的書き出し）**
   - 初回 HTML はシェル＋最小テキスト。本文は React ハイドレーション後
   - 例: `/question-sets` の取得結果は UI 枠（Sign In / Create…）が中心で、**問題文・解説の羅列が HTML 上見えにくい**
   - `/trial-question-sets` では教科書タイトル程度は見えるが、中身（Markdown 全文）は別ルート・JS 依存

4. **「学習アプリの操作画面」が主で、記事・ガイド・About が弱い**
   - トップは機能紹介＋ CTA が中心（悪いわけではないが、**単体では薄い**と判断されやすい）
   - 運営者情報・更新履歴・使い方の長文コンテンツが公開サイト上で目立たない

**対策の方向性（コンテンツ）**

- [ ] ベータ表記を「審査用の公開面」では弱める、または **完成機能だけを前面** に出す（準備中機能はログイン後のみ等）
- [ ] **公開インデックス用の静的ページ** を増やす  
  例: 各デフォルト問題集 `/sets/toeic-50`、教科書 `/learn/decision-trees` の **SSR/SSG またはビルド時 HTML** で概要＋目次＋一部本文
- [ ] `sitemap.xml` を実 URL と一致させ拡張（後述 B のパス不一致も修正）
- [ ] 「About / 運営者 / このサイトで学べること」ページ（日本語・英語）
- [ ] ブログやリリースノートは必須ではないが、**更新の継続性** が分かる何かがあると有利

### B. 「パブリッシャーコンテンツのない画面」に広告コードが載っている（有力）

ポリシー: **ログイン・ナビ・モーダル・エラー・コンテンツなし** などに広告を置かない。

#### B-1. 全 HTML に AdSense スクリプトを注入

`frontend/scripts/inject-adsense.js` は **`dist` 内のすべての `.html`** に `adsbygoogle.js` を挿入する。

影響しうるルート例（Expo export により生成）:

- `/login`, `/register`, `/verify-otp` … **認証・ナビゲーション**
- `/+not-found` … **エラー／案内**
- `/premium-success`, `/premium-cancel` … **決済結果の中間画面**
- `/dashboard`, `/settings`, `/mypage` … **アプリ UI（ログイン後・noindex でもスクリプトは読み込まれる）**

審査時に Google がこれらの URL を開くと、「行動目的の画面に広告タグがある」と判断されうる。

**対策の方向性（実装）**

- [ ] AdSense スクリプトは **コンテンツページのみ** に限定（例: トップ、公開問題集ランディング、教科書、規約類はタグのみでユニットなし、等）
- [ ] `inject-adsense.js` を **allowlist** 化するか、ログイン必須ルート用 HTML からは **script ごと削除**
- [ ] `WebThirdPartyScripts.tsx` も同様に、ルート条件で読み込みを制限

#### B-2. アプリ画面への `AdBanner` 配置

`AdBanner` が載っている画面（ダッシュボード、学習記録、AI ダッシュボード、問題集一覧、クイズ結果など）は、**操作・一覧・ナビ中心** で、周囲の「読むコンテンツ」が少ない。

**対策の方向性**

- [ ] バナーは **問題文＋解説が常に見える学習画面の下** など、本文と一体のレイアウトに限定
- [ ] ダッシュボード・設定・空状態一覧からは **広告ユニットを外す**（スクリプトも可能なら外す）

#### B-3. クイズ中の `InterstitialAdModal`

`QuizEngine.tsx` + `InterstitialAdModal.tsx`:

- 20 問ごとに **モーダル全面** で広告
- 5 秒間閉じられないカウントダウン

これはポリシー上 **「アラート／中断 UI」に近い広告** と解釈されるリスクが高い。

**対策の方向性**

- [ ] インタースティシャル風モーダル広告は **Web AdSense 審査通過まで無効化**
- [ ] 代替: 問題と解説の **ページ内インライン 1 ユニット**（スクロールで自然に見える位置）
- [ ] 強制待ち時間は撤廃または短縮（ポリシー・ UX 両面）

### C. 手続き・技術設定（警告の「要確認」部分）

| 項目 | 現状メモ | 対策 |
|------|----------|------|
| 支払い情報 | 未設定の警告 | AdSense で住所・支払い方法を完了 |
| サイトをリンク | 要リンク | 正しいプロパティ（`https://ai-practice-book.com`）でサイト追加・コード設置確認 |
| 所有権 | 要確認 | `google-site-verification`（`index.tsx` / inject）、`public/google644c9dfdc82bc46a.html`、`ads.txt` の **いずれか一貫** で Search Console と AdSense 双方を確認 |
| `ads.txt` | 本番で `google.com, pub-9679910712332333, DIRECT, ...` 確認済 | コンソールの「ads.txt 問題なし」まで確認 |
| 広告ユニット ID | `EXPO_PUBLIC_AD_SLOT_WEB` 未設定時 **`1234567890` プレースホルダ**（`AdBanner.web.tsx`） | 審査前に **本番ユニット ID** を発行・設定（`docs/TODO_広告.md`） |
| プライバシーポリシー | GA の記載はあるが **AdSense / パーソナライズド広告の明示が薄い** | Cookie 条項に Google AdSense、第三者広告、オプトアウトリンク等を追記 |

### D. URL・SEO の不整合（間接要因）

- トップの CTA は `/(trial)/trial-question-sets`（本番 `/trial-question-sets`）だが、**sitemap は `/question-sets`**
- `/question-sets` は `(app)/question-sets/index.tsx` から trial 画面を re-export しているため動くが、**canonical・内部リンク・sitemap の主 URL を統一** した方がよい
- ログイン後トップは `noindex`（`index.tsx`）— 良いが、**ログイン前の公開 URL の厚み** が審査の主戦場

### フェーズ 1: ポリシーに直結（コード）

1. [ ] 全ページ AdSense 注入 → **公開コンテンツページのみ** に変更

## 5. 結論（短く）

- **有用性の低いコンテンツ:** 「ベータ＋準備中が多い学習 **アプリ**」「インデックス可能な **読み物が少ない SPA**」が主因と考えられる。公開用の **問題集・教科書ランディング** を HTML として厚くするのが本丸。
- **コンテンツのない画面での広告:** **全ページ script 注入** と **ダッシュボード／モーダル広告** がポリシー文言と一致しやすい。審査前に **配置と注入範囲を絞る** べき。
- **要確認（支払い・リンク・所有権）:** ポリシーとは別の必須手続き。`ads.txt` は問題なさそうだが、コンソール上で所有権・サイトリンクを完了させる。

「1/2」の続きで AdSense のスクショや特定 URL があれば、どの URL が審査でフラグされたかまで踏み込める。
