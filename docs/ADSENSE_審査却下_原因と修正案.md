# AdSense 審査却下：何がまずいか／修正案

対象サイト: [https://ai-practice-book.com](https://ai-practice-book.com)  
AdSense パブリッシャー ID: `pub-9679910712332333`  
調査日: 2026-10-16  
対象コード: 本番 Web（Expo / React Native Web の静的書き出し）

この文書は、AdSense コンソールに出ている警告・ポリシー違反を **本番サイトと実装に突き合わせた診断** と、再申請までの修正案です。コード変更そのものは含みません。

---

## 1. 結論

Google が見ているのは「完成した学習サイト」ではなく、**作成中の Web アプリの殻** です。

コンソールの2つのポリシー指摘は別問題ではなく、同じ根因です。

| 指摘 | このサイトでの実体 |
|------|-------------------|
| パブリッシャーのコンテンツを含まない画面に広告がある | ダッシュボード・一覧・結果・20問ごとの強制モーダルなど、**操作画面**に AdSense を置いている |
| 有用性の低いコンテンツ | クローラーが読める本文がほぼ無く、トップは「準備中」「ベータ」、公開の問題集一覧は空 |

**広告ユニットを増やす・再申請ボタンを押すだけでは通りません。**  
先に「未完成のアプリ画面から広告を外す」ことと、「クローラーが HTML として読める独自コンテンツを公開する」ことが必要です。

---

## 2. コンソールメッセージの分解

表示されていた文言を、**運用タスク** と **ポリシー違反** に分けます。

### 2.1 運用（コードでは直らない）

| メッセージ | 意味 | 対応場所 |
|------------|------|----------|
| お支払い情報を追加し、サイトを AdSense にリンク | 収益化の口座・税務情報未登録、またはサイト未紐づけ | AdSense 管理画面 |
| サイトの所有権を確認 | Search Console / ads.txt / meta での所有確認が未完了、または未承認 | AdSense + Search Console |
| サイトは広告を表示できない状態 | 上記未完了 **または** ポリシー審査が通っていない結果 | 審査通過後に自動解除されることが多い |

所有権まわりで既に入っているもの:

- `https://ai-practice-book.com/ads.txt` は配信済み（`google.com, pub-9679910712332333, DIRECT, f08c47fec0942fa0`）
- ビルド後 HTML に `google-site-verification` と `google-adsense-account` を注入（`frontend/scripts/inject-adsense.js`）
- トップの未ログイン時にも同じ verification meta を JS でセット（`frontend/app/index.tsx`）

**ads.txt はあるので、所有権は「ファイル不足」より「コンソール側の確認操作が未完了」か「審査側がサイトを未承認のまま」の可能性が高いです。** お支払い情報はコードでは扱えません。

### 2.2 ポリシー違反（サイト側の中身）

Google が明示している禁止は次のとおりです（[公式](https://support.google.com/publisherpolicies/answer/11112688?hl=ja)）。

1. コンテンツが無い、または有用性の低い画面に広告を置く
2. **作成中** の画面に広告を置く
3. アラート・ナビゲーション・操作目的の画面に広告を置く

加えて「有用性の低いコンテンツ」は、サイト全体が次を満たしていない、という判定です。

- 独自の価値がある情報・ツール・サービス
- 継続的なキュレーションとメンテ
- ユーザーの純粋な関心を集め、維持できている

審査対象は **広告コードがある1ページだけではなく、サイト全体** です。

## 3. 審査官・クローラーが実際に見ているもの

2026-10-16 時点の本番と、実装の突き合わせです。

### 3.1 インデックス対象が極端に少ない

`frontend/public/sitemap.xml` に載っている URL は次の5件だけです。

| URL | 本番で見える中身 |
|-----|------------------|
| `/` | キャッチコピー + 機能カード4枚（各1行）+ 「準備中」の料金/マーケット + CTA |
| `/question-sets` | **「No question sets yet. Create your first one!」**（空） |
| `/tokusho` | 特商法。文章はあるが商品説明ではない |
| `/terms-of-service` | 利用規約 |
| `/privacy-policy` | プライバシーポリシー |

規約・特商法は「信頼の固定ページ」にはなりますが、**広告を載せるパブリッシャーコンテンツにはなりません。**

### 3.2 トップページが「作成中」に見える

未ログインの `/` は、審査官に次のシグナルを出しています。

- 初回に「ベータ版です。機能・挙動・デザインは予告なく変更される場合があります」モーダル
- プレミアム: **準備中**
- 問題集マーケットプレイス: **準備中**
- 機能説明がアイコン + 1行（「CSVで簡単に問題集を作成」など）で、段落の本文がほぼ無い
- 「登録なしで試す / 今すぐ始める / ログイン」だけの操作画面に近い

Google は「サイトがまだ作成中、またはテンプレートのみの段階での申し込みは控えてください」と明記しています。  
**「準備中」バッジがトップの主コンテンツになっている時点で、この条項に正面から抵触します。**

### 3.3 サンプル問題集がクローラーから見えない

リポジトリには次のような教材データがあります。

- 問題 CSV（TOEIC、英単語、ビジネス英語、AWS ML、深層学習、プロンプト工学など）
- 教科書 Markdown（決定木、機械学習など `docs/textbook/`）

しかし公開の `/question-sets` は空です。理由は実装です。

1. デフォルト問題集は `loadDefaultQuestionSets()` → `localStorage`（`AsyncStorage`）に書き込む（`frontend/app/(trial)/_layout.tsx`、`localStorageService.ts`）
2. 一覧は **その端末の localStorage を読む**（`trial-question-sets.tsx`）
3. Googlebot は JS を実行しても、ユーザー端末の localStorage を持たない
4. その結果、クローラーには「問題集はまだありません」と出る

加えて `robots.txt` は次を禁止しています。

```
Disallow: /question-sets/
Disallow: /quiz/
Disallow: /flashcard/
Disallow: /set/
```

たとえ問題詳細・教科書が URL を持っていても、**クローラーは辿れません。**  
sitemap の `/question-sets` は許可されていますが、中身が空なので無意味です。

### 3.4 SPA のため HTML 本文が薄い

本番は Expo Web の静的書き出し + クライアント描画です。

- 初期 HTML はアプリシェル
- 本文・規約・一覧は JavaScript 実行後に出る
- 規約ページを fetch しても、見出し番号だけ残って本文が欠けることがある（今回の取得でもその兆候あり）

AdSense の一次審査はボット中心です。**CSR の Web アプリは「中身が無いサイト」と誤認されやすい**、というのがこの却下の技術的な核です。

## 4. 指摘1：コンテンツの無い画面に広告がある

### 4.1 いま広告を置いている画面

`AdBanner`（中身は AdSense `<ins class="adsbygoogle">`）の設置箇所:

| 画面 | ファイル | 画面の性質 | ポリシー上の判定 |
|------|----------|------------|------------------|
| ログイン後ダッシュボード | `frontend/app/(app)/dashboard.tsx` | メニュー（問題集・作成・ログアウト） | **ナビゲーション画面。禁止** |
| AI ダッシュボード | `frontend/app/(app)/ai-dashboard.tsx` | 分析ツールの入口 | 操作画面。コンテンツページではない |
| 学習計画 | `frontend/app/(app)/learning-plan.tsx` | 計画ツール | 同上 |
| 学習記録 | `frontend/app/(app)/study-records.tsx` | 記録一覧 | ユーザーデータ。パブリッシャー記事ではない |
| 自分の問題集一覧 | `frontend/app/(app)/my-question-sets/index.tsx` | 管理一覧。空になりうる | 空・操作画面 |
| クイズ結果 | `frontend/app/(app)/quiz/result.tsx` | スコア表示（完了画面） | **手続き完了・デッドエンド。禁止例そのもの** |
| ストア | `frontend/app/(app)/store.tsx` | 本番ではリダイレクトだがコード上はバナーあり | 準備中機能。作成中画面 |

加えて全ページで AdSense スクリプトを読み込んでいます。

- 開発: `_layout` → `WebThirdPartyScripts.tsx` が **全画面** に `adsbygoogle.js` を挿入
- 本番ビルド: `inject-adsense.js` が `dist/**/*.html` **全部** に script + meta を注入

ログイン、OTP、404、ローディング、空一覧にもスクリプトが載ります。  
ユニットが無くても「このサイトは広告配信前提」と審査されます。

### 4.2 20問ごとの強制モーダルは特に危険

`QuizEngine.tsx` が 20 問ごとに `InterstitialAdModal` を出し、**5秒間閉じられない**（`CLOSE_DELAY_SEC = 5`）。

これは次のポリシーに同時に触れます。

- [コンテンツの無い画面](https://support.google.com/publisherpolicies/answer/11112688?hl=ja)（操作・割り込み）
- [広告がコンテンツや操作を妨害](https://support.google.com/publisherpolicies/answer/11035030?hl=ja)（オーバーレイ、閉じるまで操作できない）
- [広告の配置](https://support.google.com/adsense/answer/1346295?hl=ja)（コンテンツ視聴前に広告を見せる、誤クリック）

Web の AdSense に、アプリのインタースティシャルをそのまま載せるのは審査前から外すべきです。ネイティブの AdMob インタースティシャルとは別物です。

### 4.3 広告ユニット自体も未完成

`AdBanner.web.tsx`:

```ts
const WEB_AD_SLOT = process.env.EXPO_PUBLIC_AD_SLOT_WEB || "1234567890";
```

本番スロット未設定ならプレースホルダです。`docs/TODO_広告.md` でも未完了扱いになっています。  
**審査通過前にダミーユニットを量産する必要はありません。** 先に「置く場所」をコンテンツページだけに絞ります。

## 5. 指摘2：有用性の低いコンテンツ

Google が再送信前に確認せよ、としている3点と、現状の対応です。

### 5.1 「信頼できる高品質な情報・ツール・サービス」

中身（問題集・教科書・AI 採点）はリポジトリにはあります。  
**公開 HTML としては存在しません。**

審査官が見るのは次だけです。

- 1画面の LP（宣伝文句）
- 空の問題集一覧
- 規約3枚
- 「準備中」「ベータ」

ツール系 SPA は、実装が良くても HTML に読める文章が薄いと「有用性が低い」になります。FAQ を LP に足すだけでは足りず、**独立した読み物（ガイド・解説・公開教材）** が必要、というのが同種サイトの通例です。

### 5.2 「継続的なキュレーションと構造のメンテナンス」

- sitemap の `lastmod` は 2026-04（約半年更新なし）
- 公開ページが増えていない
- マーケットもプレミアムも「準備中」のまま
- デフォルト問題集はクライアント初期化依存で、公開カタログになっていない

「メンテされているサイト」ではなく「作りかけのアプリ」に見えます。

### 5.3 「ユーザーの純粋な関心を集め、維持している」

これはトラフィックと再訪の話です。新規ドメイン + ベータ + 主要機能が準備中、では数字も付きにくいです。  
コンテンツを厚くしたあと、Search Console でインデックスと検索流入を確認してから再申請した方が通りやすいです。

## 6. 修正案（優先度順）

再申請は、下の P0 を公開反映したあとです。先にボタンを押さないでください。

### P0-A. 運用（AdSense コンソール）

1. お支払いプロフィール（氏名・住所・口座・税務）を完了する
2. `ai-practice-book.com` をサイトとしてリンクする
3. 所有権確認を完了する（Search Console 連携、または既存の verification meta / ads.txt）
4. **ポリシー修正が終わるまで「審査をリクエスト」は押さない**

### P0-B. 広告を「コンテンツの無い画面」から外す

再申請前の必須です。

1. 次から `AdBanner` を外す
   - `dashboard.tsx`
   - `ai-dashboard.tsx`
   - `learning-plan.tsx`
   - `study-records.tsx`
   - `my-question-sets/index.tsx`
   - `quiz/result.tsx`
   - `store.tsx`
2. Web では `InterstitialAdModal` を出さない（少なくとも審査通過まで。ネイティブ AdMob は別判断可）
3. `adsbygoogle.js` を全 HTML に注入するのをやめる
   - 審査中は **公開コンテンツページだけ** に script を置く
   - ログイン・OTP・ダッシュボード・空一覧・結果・404 には置かない
4. プレースホルダ `data-ad-slot=1234567890` を本番に出さない

置いてよいのは、**パブリッシャーが書いた本文が画面の主領域を占めるページ** だけです。例:

- 公開ガイド記事
- 公開教科書（HTML として読める）
- サンプル問題の解説ページ（問題文 + 解説の段落がある）

トップの CTA だらけの画面、メニュー、完了画面には置かない。

### P0-C. 「作成中」シグナルを消す

トップから次をなくすか、機能を本当に公開する。

| いまの表示 | 取りうる修正 |
|------------|--------------|
| プレミアム「準備中」 | 課金を出す **または** トップから料金カードごと外す |
| マーケット「準備中」 | ストアを出す **または** トップ・特商法から売買の話を落とす |
| ベータ版モーダル | 審査期間は出さない。必要ならフッターの一行にする |
| 「データは消える」「ログイン非推奨」の長い警告 | 未完成印象を強める。審査中は目立たせない |

特商法・利用規約は「問題集を売買できるプラットフォーム」と書いています。トップが「マーケットは準備中」だと、**未完成 + 記載の不一致** になります。

### P0-D. クローラーが読める本文を公開する

目安（再申請の最低ライン）:

- **独自の長文ページを 8〜15 本**（1本 1,500〜3,000 字以上、タイトルだけでなく段落）
- テーマはこのプロダクトの専門性に寄せる（暗記、忘却曲線、英単語、TOEIC、機械学習の入門解説など）
- **AI で量産した薄いまとめは逆効果**（スパムポリシー）
- 運営者・目的・問い合わせがページとして辿れる

すぐ使える既存資産:

| 資産 | いまの状態 | やるべきこと |
|------|------------|--------------|
| `docs/textbook/*.md` | アプリ内・API 依存。`/set/` `/textbook/` は robots 禁止 | **公開 URL の静的 HTML** にする（SSR またはビルド時生成）。robots で許可し sitemap に載せる |
| デフォルト問題 CSV | localStorage にしか無い | サーバーまたは静的 JSON で一覧・詳細を描画。Googlebot が空文言を見ないようにする |
| CSV 作成ガイド（`docs/問題集生成_CSV指示書.md` など） | リポジトリ内のみ | `/guides/csv` のような公開ヘルプにする |

`/question-sets` が「問題集はまだありません」のまま再申請してはいけません。

### P0-E. クローラー制御を「中身があるページだけ」に揃える

審査中の推奨:

- **index してよい**: `/`（本文を厚くしたあと）、公開ガイド、公開教科書、公開サンプル問題、特商法、規約、プライバシー、運営者情報
- **index してはいけない**: ログイン、OTP、ダッシュボード、設定、空のユーザー一覧、クイズプレイ中、結果、フラッシュカード操作画面

`robots.txt` の `Disallow: /question-sets/` は、公開カタログを作るなら子パスを許可する必要があります。逆にユーザー固有の `/question-sets/{uuid}` は出し分けが必要です。

sitemap は「中身のある URL だけ」に更新し、Search Console に再送信します。

### P1. トップを「アプリの起動画面」から「サイト」に変える

審査官が最初に開くページです。最低限入れるもの:

1. 誰向けか、何が解決するか、を **複数段落** で書く
2. 公開サンプル（問題・教科書）への内部リンク
3. 使い方ガイドへの内部リンク
4. 運営者（氏名または屋号、連絡先。特商法と一致）
5. 準備中機能を主視覚にしない

機能カード4枚 + CTA 3つ、だけでは不足です。

### P2. 関心の維持（再申請を急がない理由）

- Search Console で公開ページがインデックスされる
- 検索または紹介で、ボット以外のアクセスが付く
- 公開教材を追加・更新した記録が残る

ドメインが新しく、公開ページが規約だけの状態で連打しても、同じ理由で落ちます。

## 8. 再申請チェックリスト

公開してから、自分でボット視点の確認をしてください。

- [ ] 未ログインのシークレットウィンドウで `/` を開く。「準備中」「ベータ」が主内容になっていない
- [ ] JS を無効にする、または `curl` / テキスト化で `/` と公開記事に **十分な日本語（または英語）の段落** がある
- [ ] `/question-sets` が「No question sets yet」ではない
- [ ] 公開教科書・ガイドが URL 直打ちで本文を返す
- [ ] ダッシュボード・結果・20問モーダルに AdSense ユニットが無い
- [ ] ログイン・空画面・404 の HTML に `adsbygoogle` を無理に入れてない（審査中は特に）
- [ ] `https://ai-practice-book.com/ads.txt` がコンソールの pub ID と一致
- [ ] Search Console で公開 URL がインデックスされている（または登録済みでエラーが無い）
- [ ] 特商法・規約・トップの「何を売っているか」が一致している
- [ ] お支払い情報・サイトリンク・所有権がコンソール上で完了している

すべて満たしてから「問題を修正しました」→ 審査リクエストです。

## 9. やってはいけないこと

- 中身を増やさずに再申請する（同じ理由で落ちる）
- 不合格だから広告を増やす
- LP にキーワードを詰め込む（「AI単語帳 AI英単語 問題集…」の meta を本文代わりにしない）
- 短い AI 記事を量産してページ数だけ稼ぐ
- 空のテストページに広告コードだけ置く
- 審査中だけダミーブログを足し、通過後に消す（再審査・無効の原因）

## 10. このプロダクト特有の判断

このサイトの本業は **Web アプリ（単語帳・問題集）** です。AdSense が本来想定しているのは **記事・教材のあるサイト** です。

取りうる方針は2つです。

### 方針 A: ドメインを「学習メディア + アプリ」にする（AdSense を通したい場合）

公開教材・ガイドをサイトの主内容にし、アプリはその先のツール、と見せる。  
広告は記事・公開教材の横だけ。アプリ操作画面には置かない。

### 方針 B: Web の AdSense を急がない

収益の主軸はプレミアムとマーケット（準備中の機能）にする。  
Web 広告は審査が通るまでオフ。ネイティブは AdMob をポリシーどおりに使う。

**今のまま（殻だけの SPA に全画面 AdSense）は、どちらの方針でも不合格です。**

方針 A を取るなら、P0-B〜E を公開してから再申請してください。方針 B なら、コンソールのポリシー指摘は「サイト側を直すか、Web 広告を諦めるか」であり、支払い情報だけ埋めても広告は出ません。
